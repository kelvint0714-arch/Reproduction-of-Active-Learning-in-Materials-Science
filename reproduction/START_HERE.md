# 从这里开始：复现论文的实际操作流程

这不是按 Day 编排的课程。操作顺序由论文复现状态决定：**锁定来源 → 跑通作者代码 → 核对论文结果 → 统一重实现 → 比较方法**。

当前只开始 P01。不要同时安装所有论文环境，也不要一开始连接真实粘合剂实验。

## 第一步：先读 P01 的复现卡

阅读：

1. [P01 论文复现卡](../papers/core/P01_PVLab_Benchmarking.md)；
2. 论文的摘要、方法、实验设置和评价指标；
3. 作者仓库 README；
4. [统一主动学习流程](../docs/02_统一主动学习流程.md)。

读完后，应能用自己的话填写：

| 问题 | P01 的答案 |
|---|---|
| 输入 \(X\) 是什么？ | 待读论文与数据后填写 |
| 目标 \(y\) 是什么？ | 待读论文与数据后填写 |
| 代理模型是什么？ | 待读论文后填写 |
| 不确定性怎样获得？ | 待读论文后填写 |
| 采集函数怎样选择下一点？ | 待读论文后填写 |
| Oracle 是什么？ | 离线复现时是公开完整数据的隐藏标签 |
| 论文怎样评价“更快发现材料”？ | 待读论文后填写 |

不知道的项目先标 `待确认`，不要凭印象补全。

## 第二步：把作者仓库放在本仓库之外

本仓库只保存我们的复现记录、配置、适配代码和结果摘要。作者代码保持独立，以便锁定来源并遵守许可证。

在本仓库根目录执行：

```bash
mkdir -p ../upstream
git clone https://github.com/PV-Lab/Benchmarking.git ../upstream/P01-PVLab-Benchmarking
cd ../upstream/P01-PVLab-Benchmarking
git rev-parse HEAD
git remote -v
```

把 `git rev-parse HEAD` 的输出写进实验日志。不要把整个作者仓库复制进本仓库，也不要在没有记录的情况下直接改作者代码。

## 第三步：检查来源，不急着运行

在作者仓库中依次确认：

```bash
git status --short
find . -maxdepth 2 -type f | sort
```

随后记录：

- 使用哪个 Notebook 或脚本；
- 数据文件在哪里；
- requirements/environment 是否存在；
- Python 和核心依赖版本；
- 论文使用哪个数据集、模型和采集函数；
- 是否有论文对应 tag、release 或 commit。

将 [论文复现检查表](REPRODUCTION_CHECKLIST.md) 复制到以后建立的 P01 实验目录再填写。

## 第四步：为 P01 建立独立环境

不同论文年份、框架和依赖差异很大，必须一篇论文一个环境。

如果作者提供环境文件，优先使用作者文件；如果没有，再根据代码建立最小环境。示例：

```bash
conda create -n al-p01-pvlab python=3.9
conda activate al-p01-pvlab
python --version
```

不要立即把所有包升级到最新版。先记录原始报错，再进行最小兼容性修复。每一次修复都要写入实验日志。

## 第五步：只运行最小入口

第一轮目标不是“得到顶刊结果”，而是确认以下链条能执行：

```text
读取一个公开材料数据集
→ 建立初始已标注集
→ 训练一个代理模型
→ 对候选池预测均值与不确定性
→ 采集函数选出下一点
→ 从公开完整数据中揭示标签
→ 更新训练集
```

运行前复制 [实验日志模板](templates/experiment_log_template.md)，写下完整命令、数据版本、随机种子和环境。运行后保存原始日志，不只保存最终图片。

## 第六步：先核对，再修改

按这个顺序推进：

1. 原作者最小示例；
2. 原作者论文配置；
3. 与论文图表或数值核对；
4. 记录无法重现之处；
5. 才开始统一重实现。

遇到旧依赖时，不要同时换数据、模型和代码结构。一次只改一个问题，否则无法判断结果变化来自哪里。

## 第七步：完成 P01 的最低交付

P01 完成时，本仓库应新增：

```text
reproduction/runs/P01/
├── README.md                # 运行方法和复现结论
├── source_lock.md           # 论文、代码 commit、数据版本
├── environment.yml         # 实际可运行环境
├── configs/                # 实验配置
├── logs/                   # 原始日志或其可追踪索引
└── results/                # 汇总 CSV 和由脚本生成的图
```

最低结果：

- Random 基线；
- 至少一个 GP 或 RF 模型；
- 至少一个论文采集函数；
- 多个随机种子；
- best-so-far 或 regret 曲线；
- 与论文结论相符、部分相符或不相符的明确说明。

## 第八步：什么时候进入下一篇

只有 P01 达到以下条件，才进入 P02：

- 能解释每个主动学习模块；
- 原始结果可以从日志重新生成；
- 已记录代码和数据版本；
- 没有把离线数据查询误称为真实实验；
- 已写出复现偏差和下一步。

P02–P10 的操作仍沿用同一流程，只替换论文、环境、数据和模型。

## 今天应该做什么

今天只做三件事：

1. 阅读 P01 复现卡并打开论文与作者仓库；
2. 克隆作者仓库到 `../upstream/P01-PVLab-Benchmarking`，记录 commit；
3. 找到一个最小 Notebook、一个数据文件和作者依赖说明。

完成后再开始安装环境。这样你是在复现论文，而不是无目的地看代码。
