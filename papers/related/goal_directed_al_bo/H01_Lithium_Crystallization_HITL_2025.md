## 这篇论文真正做了什么

论文针对含杂质盐水制备电池级碳酸锂的连续结晶过程，把数据模型、帕累托分析、专家判断和真实实验连接起来。核心不是单独训练一个预测器，而是让模型推荐、专家收缩或修正空间、实验验证和数据更新反复循环。

公开材料显示其流程包括：

1. 用拉丁超立方等方法构造候选条件；
2. 用回归模型预测杂质相关结果并进行帕累托/NSGA-II 分析；
3. 由专家检查物理可行性、调整边界和选择实验；
4. 后续使用高斯过程分类学习可行/不可行边界；
5. 在决策边界附近继续选择有信息的实验并更新模型。

论文报告通过 38 次真实实验获得电池级条件，并把对镁杂质的容忍范围扩展到 6000 ppm。它证明了高效闭环和专家知识的作用，但没有证明在连续参数空间中找到了严格的全局最优。

## 正确分类

```text
人在回路 AL
+ 可行域/分类边界学习
+ 多目标过程优化
+ 真实实验闭环
```

因此它是 `AL+BO/HITL hybrid`，不是纯粹的全局回归 AL，也不应仅凭帕累托前沿写成“贝叶斯全局优化”。

## 数据和算法映射

| 模块 | 论文中的内容 |
|---|---|
| 输入 | 连续结晶工艺条件和盐水杂质水平 |
| 输出/标签 | 产品质量、杂质、收率或是否达到电池级要求 |
| 回归阶段 | 多个目标的预测与帕累托分析 |
| 分类阶段 | GPC 学习满足要求的可行域和决策边界 |
| 人类作用 | 修正搜索边界、检查可执行性、解释结果并批准实验 |
| Oracle | 真实连续结晶实验 |
| 主要评价 | 用较少实验找到可行工艺并扩大杂质容忍范围 |

## 公开资产与已知缺口

作者仓库和 Zenodo 提供原始/清洗/生成数据、环境文件、Dockerfile、脚本和带输出的论文复现 notebook，许可证也明确。

但核验时发现，GitHub 主分支中部分模块化脚本近乎空文件，README 宣称的脚本入口不能直接视为已经可运行。现阶段应：

- 优先使用 Zenodo v1 的 `Paper_Reproduction_with_Cell_Outputs.ipynb` 对照已有输出，再运行无输出版本；
- 若从 GitHub 获取大文件需检查 Git LFS；更稳妥的入口是 Zenodo ZIP；
- 固定数据版本、环境和随机种子；
- 先复现图表与离线模拟，不宣称复现了真实连续结晶装置；
- 将专家干预逐轮写入日志，否则无法复现 HITL 决策。

因此软件/数据复现性评为**中等**，真实实验闭环复现性评为**高难度**。

## 最小复现建议

1. 下载 Zenodo 固定归档，记录校验值。
2. 运行带输出 notebook，核对原始数据到清洗数据的转换。
3. 回放 Pareto 分析和 GPC 决策边界。
4. 比较 Random、无专家边界和原论文 HITL 规则。
5. 记录每轮候选空间如何被人类修改。
6. 只在离线结果与论文一致后，再讨论能否迁移到其他材料过程。

## 对本项目的价值

它最有价值的部分不是某一个模型，而是**人在真实材料闭环中扮演什么角色**：算法提出下一批候选，材料专家负责安全、可制备性和搜索空间约束。未来粘合剂实验也应采用这种“模型推荐—化学组审核—实验回填”的结构。
